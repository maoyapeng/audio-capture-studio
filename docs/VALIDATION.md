# 0.1 验证记录

验证环境：Linux，Python 3.12.10，PySide6 6.9.3，Qt offscreen。

运行命令：`python -m unittest discover -s tests -v`。

9 项自动测试通过，覆盖：

- 两台模拟输入分别保存 8 通道 / 2 通道文件，并检查信号、采样率和文件内容。
- USB 输入断开时保留有效的部分录音，报告异常。
- 探测所选采样格式的可用通道数，不静默减少通道。
- 采集信息不写入密码；Windows 文件名特殊字符和保留名处理。
- 远程终端命令回显不被误判为采集结束；结束后才取回文件。
- 每次远端输出使用唯一文件名，避免取回旧文件。
- 远程文件通道参数不符时不标为成功，保留下载内容。
- 桌面界面选择设备、开始 / 停止，四台演示设备分别生成文件及完整采集清单。

已人工查看 Qt 实际窗口截图，检查 USB 通道面板和远程日志面板。

尚未验证：Windows 真实 USB 驱动与热插拔、多设备长时间压力、真实 SSH / Telnet / ADB 设备和网络故障、Windows EXE 打包。远程流程使用受控传输对象测试，不代表已连接真实设备。

## Windows 多设备选择回归验证（2026-10-31）

后续实机检查：Realtek 2 通道在 WASAPI 共享模式下通过 48000 Hz 参数检查，16000 Hz 不通过；POROSVOC_20X3H 9 通道通过 16000 Hz，48000 Hz 不通过。两者同时打开流均返回 Invalid device (-9996)，没有采集到音频帧。独立尝试 MME / DirectSound 也报后端错误。不能宣称实机录制通过，驱动、权限和执行环境原因尚待区分。已将本地配置分别设为上述通过参数检查的采样率。

修复后回归共 24 项，23 项通过，仍只有 PnP 集成测试受权限限制失败。新设备使用驱动默认采样率；打开音频流成功后才发送采集开始事件；打开失败包含设备和参数，且不会被标记为已保存。

环境：Windows，Python 3.12.14，PySide6 6.12.0，Qt offscreen。

23 项测试中 22 项通过；`test_windows_inventory_command_executes` 因当前执行环境的 Windows PnP 查询权限受限失败，真实 USB 硬件分类尚未验证。临时目录使用工作目录，并仅在测试启动进程中调整 Python 临时目录的创建权限以兼容执行环境。

新增覆盖：按设备保留其他驱动独有的输入、同名不同端点不合并、接口数量不一致时保留条目、已选断开设备仍可见，以及跨驱动切换筛选后仍同时录制 9 通道和 2 通道设备。最后一项使用演示信号，检查两台设备同时处于运行状态、分别生成有效音频、清单通道数和保存状态正确；不代表双 USB 实机同时录制已通过。
